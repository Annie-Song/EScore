# 迭代闭环

你是本项目的迭代执行者。收到 /loop 后严格按五阶段推进，每阶段完成再进入下一阶段。关键实现方案（影响架构、用户体验、核心功能性能、总成本）用 AskUserQuestion 让用户拍板，不要擅自决定。

## 产物文件

| 文件 | 用途 |
| --- | --- |
| DOCX/问题与优化反馈/迭代反馈表.md | 问题状态唯一入口 |
| DOCX/bugLOG.md | bug 日志 |
| DOCX/压力测试报告.md | 压测结果 |
| DOCX/版本迭代报告.md | 每版本报告 |

## Phase 0 启动

1. 确定版本号（语义化三段：主.次.修订）
2. 读取上轮产物：迭代反馈表、bugLOG、上一版版本迭代报告
3. 确认环境可运行、依赖就绪

## Phase 1 规划

4. 从迭代反馈表筛"待处理"且 P0/P1 的问题，加用户新需求，按优先级排序
5. 为每个任务写 plan：目标、方案、涉及文件、验收标准（DoD）、依赖关系
6. 每个任务的方案与用户确认；关键方案用 AskUserQuestion 给多选

## Phase 2 执行（内循环，逐任务）

7. 实现任务
8. 写并跑单元测试，通过继续，失败回 7
9. 有 bug：可修 → 修复并记入 bugLOG.md；跨版本无法解决 → 记入迭代反馈表标"待处理/已延后"
10. 更新迭代反馈表（任务状态 → 已完成）
11. 按 git 规范提交
12. 进入下一子任务

## Phase 3 联合测试

13. 端到端联调（首页、OCR、评分全链路）+ 回归测试
14. 涉及核心功能（OCR、评分、批改链路）→ 压测记入压力测试报告.md
15. 有 bug 回 Phase 2

## Phase 4 总结

16. 生成版本迭代报告：目标、完成项、遗留问题、度量数据、经验教训
17. 更新迭代反馈表收尾
18. loop 自省：哪里卡、哪里冗余，输出工作流优化建议
