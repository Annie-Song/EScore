# 项目规范（Grade-your-homework）

本文件是项目级规范，优先级高于全局规范，每次会话自动加载。代码与项目的具体规则以本文件为准。

## 代码结构化（硬约束）

代码按模块分文件夹组织，禁止在根目录堆放业务文件：

| 目录 | 职责 |
| --- | --- |
| app/ | 路由与请求处理 |
| services/ | 业务逻辑（评分、OCR、语义匹配） |
| utils/ | 通用工具 |
| tests/ | 测试 |

硬性规则：

1. 一个文件不超过 5 个公开函数或方法。
2. 一个文件不超过约 200 行，超出拆分为多个文件。
3. 每个 Python 包目录含 __init__.py。
4. 现有根目录扁平文件（server.py、scoring.py、grade.py）在重构时迁入对应模块。

## 代码风格

1. Python 严格遵循 PEP 8，含类型注解与 docstring。
2. 变量名、函数名用英文 snake_case，类名用 PascalCase。
3. 代码标识符用英文，注释根据上下文用中文。

## 测试风格

1. 使用 pytest。
2. 命名 test_功能_场景。
3. 每个核心函数或模块有单元测试。
4. 外部依赖（DeepSeek API、OCR 模型）必须 mock，测试可离线独立运行。

## 复用习惯

1. 重复逻辑抽为工具函数。
2. 常量集中在 config 模块。
3. 优先使用成熟第三方库，避免重复造轮子。

## 版本号

采用语义化三段：主版本.次版本.修订。重大重构升主版本、新功能升次版本、bugfix 升修订。当前版本 1.1.0。
